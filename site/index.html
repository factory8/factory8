The AI-Native SDLC in 5 minutes

Same six stages, same control objectives — but a loop instead of a line, with AI in every stage and humans governing at the gates.

Why change?

Code isn't the bottleneck. Agents build in hours; plan, review/test and deploy still run at human speed.
Old controls don't scale. Line-by-line human review and weekly committees can't keep up with agent output.
So: same controls, new enforcement. Policy lives in versioned files and hooks, applied as the agent acts.
Humans stay accountable. Attention moves from watching edits to approving artifacts at gates.

2 · Governance: the agent acts up to the gate, never past it

Advisory controls make violations rare. Deterministic controls make them (near) impossible. Separation of duties: the agent that wrote the code cannot approve it.

Skills / CLAUDE.md guide; hooks, managed settings, sandbox, branch protection and per-environment MCP tools enforce. Autonomy is tiered: dev free, staging middle, prod human-authorized. full size · source

3 · Closing the loop (Maintain)

Detection is deterministic (rolling baseline, no model). Claude is invoked only after a breach, and the σ tier sets what it may do: 1σ log, 2σ diagnose read-only, 3σ propose a PR or pre-approved runbook. Every incident becomes a permanent eval. full size · source

Building blocks

CLAUDE.md — day-one context for the agent; a mistake made twice goes in. Under a page.
Skills — org policy as versioned, owner-signed instructions. Advisory.
Hooks — allow / ask / block on every action. Deterministic; non-negotiable ones in managed settings.
Subagents & worktrees — verifier, simplifier, researcher; 2–3 parallel sessions per engineer, limited by review capacity.
Evals in CI — 20–50 real tasks re-run on any change to config; every incident adds one.
Source of truth — name exactly one per artifact (repo or Jira etc.); minimum bar is cross-linking record ID ↔ commit SHA.
